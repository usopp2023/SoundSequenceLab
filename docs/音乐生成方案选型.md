# 音乐生成方案选型（给合伙人讨论）

> 日期：2026-06-06。背景：情绪分析已用阶跃星辰跑通；**音乐生成这一环要选一条能长期落地的路**。本文给两个候选 + 取舍，供决策。

> **【现状更新 2026-06-06】** 已先把"自建 Suno"这条**跑通并接进产品**（自建 suno-api + 有头浏览器生成，绕开了失效的 token/验证码流程），端到端实测出真民乐。详见 `docs/Suno接入说明.md`。
> 但它的局限仍在（有头浏览器、cookie 过期、Suno 改版、真民乐天花板"国风近似"）。所以本文的取舍依然成立：**Suno 自建 = 当前能用的过渡**；**ACE-Step（方案 A）= 长期、真民乐（LoRA）的方向**，等有 GPU 再上，换个 `MusicService` 适配器即可。

---

## 一、为什么不能继续用现在这条（Suno 自建爬虫）

- **Suno 没有官方 API**（确认过）。市面上能用的 Suno 接入都是第三方：要么自己跑爬虫，要么付费托管。
- 我们试的 `gcui-art/suno-api`（自建爬虫）已经走到："cookie 通了（账号 550 额度）、国内代理也配通了（能加载 suno.com）"，但**最终卡在它的网页自动化选择器过时**（Suno 改版，库没跟上），而且**再往后还要付费 2captcha 过人机验证**。
- 本质问题：**"爬网页"方案会随 Suno 每次改版反复失效**，维护成本高、不可控。不适合作为产品的长期底座。

> 结论：换路。下面两个是真正能落地的方向。

---

## 方案 A：ACE-Step 1.5（开源模型，自建）⭐ 推荐

开源音乐生成大模型（MIT 协议），定位就是"开源版 Suno 替代"。

**它解决了我们所有痛点**
- **本地/国内跑** → 没有 GFW、没有人机验证、没有 cookie、没有第三方依赖、**生成免费无限次**
- 自带 **REST API**（`acestep-api`，`localhost:8001`，异步），我们后端只要写个适配器就接上，**前端和异步流程完全不用改**
- **支持纯器乐 + 中文 + BPM/调式/乐器/时长控制**——正好喂我们"9 桶情绪"算出的民乐参数
- 速度快：RTX 3090 上一首 <10 秒（A100 <2 秒）
- **数据不出境**（prompt/素材都在自己机器），隐私上更干净

**杀手锏（和我们的产品最相关）**
- **能 LoRA 微调**：用约 8 首素材、12G 显存机器约 1 小时，就能训出一个风格。
- 意味着可以用**演奏者的二胡/古筝真实录音**去微调，把"听起来像国风"练成**真正的民乐技法质感**——这正是 proposal 里反复强调的灵魂卖点和研究护城河（"情绪 70% 在演奏技法里"）。Suno/托管 API 给不了这个。

**成本 / 前提**
- 需要一块 GPU：
  - 本地 NVIDIA 显存 **≥6G** 就能跑（甚至 Apple Silicon Mac / CPU 慢跑）
  - 没有本地显卡 → 租**国内云 GPU**（autodl 等，按小时约 ¥1–2），全程国内、不碰墙
- 一次性：要下载模型权重（数 GB，可走国内镜像 hf-mirror）；装一次环境（uv/docker，有现成整合包）
- 跑起来后**零边际成本**（自己的电费/云时长）

**缺点 / 风险**
- 要自己运维一个 GPU 服务（部署、常驻）
- 出厂民乐质量是"国风近似"（和 Suno 同级），**要靠 LoRA 才能上到"真民乐"**——但这恰好是我们想做的事

---

## 方案 B：托管 Suno API（付费第三方）

如 `sunoapi.org` / apiframe / EvoLink：第三方把 Suno 的 cookie/验证码/改版都在他们服务端搞定，给我们一个干净的 REST API。

- **接入**：Bearer key 鉴权，异步（提交→轮询/回调），支持纯器乐；我们写个适配器对接（它的接口和 gcui-art 不完全一样）
- **质量**：Suno 质感（通用流行曲上比开源略好）
- **成本**：按次付费，约 **$0.1/首**（EvoLink $0.111/首；apiframe $19/月 ≈ 3000 额度 ≈ 270 首，有 300 免费额度试）
- **优点**：不用碰 GPU、不用运维、上手最快
- **缺点**：
  - **按次花钱**，量大持续支出
  - 端点在海外，**国内可能仍要代理**
  - prompt 数据出境给第三方
  - **给不了民乐 LoRA**（拿不到模型，只能用它给的风格词），民乐天花板就是 Suno 的"国风近似"
  - 依赖第三方服务的稳定性与合规

## 三、其它看过但不选的

| 方案 | 为什么不选 |
|---|---|
| MusicGen(Meta) / DiffRhythm / YuE | 开源，但质量/活跃度不如 ACE-Step |
| Udio / Stable Audio / ElevenLabs Music / Mubert | 偏西方曲风，民乐弱，且海外 |
| 国内消费级（网易天音 / 天工 / 海绵音乐） | 基本没开放开发者 API，可控性差、拿不到模型 |

## 四、对比速览

| 维度 | A. ACE-Step 自建 | B. 托管 Suno API |
|---|---|---|
| 国内可用性 | ✅ 本地/国内云，不碰墙 | ⚠️ 海外端点，可能要代理 |
| 验证码/cookie/改版 | ✅ 完全没有 | ✅ 第三方代管 |
| 单次成本 | ✅ 免费（自摊 GPU/电费） | ❌ ~$0.1/首，持续 |
| 上手速度 | ⚠️ 要部署 GPU 服务 | ✅ 拿 key 即用 |
| 运维 | ❌ 自己维护 | ✅ 无 |
| 民乐质量 | 出厂"国风近似"，**可 LoRA 上真民乐** | "国风近似"封顶 |
| 数据隐私 | ✅ 不出境 | ❌ 出境给第三方 |
| 与 proposal 护城河契合 | ✅✅ 演奏者素材→LoRA | ❌ 商品化、无差异 |
| 我们代码改动 | 写个 `ACEStepMusic` 适配器，前端/异步不动 | 写个 `SunoApiMusic` 适配器，前端/异步不动 |

> 我们后端的 `MusicService` 是可插拔抽象，**无论选哪个，都是加一个适配器 + 改一个配置开关，前端和异步生成流程一行不用动。**

## 五、推荐

**走 ACE-Step 自建。** 理由：
1. 一次性解掉国内全部痛点（墙、验证码、cookie、持续成本、可控性、数据出境）。
2. **唯一能把民乐做到"真"的路**（LoRA + 演奏者素材）——这是产品的差异化/护城河，Suno 系给不了。
3. 我们的架构换它几乎零成本（一个适配器）。

**托管 Suno API** 适合做"这周就想先有个能出曲的东西、暂不碰 GPU"的过渡——可以并行先接它跑 demo，长期切 ACE-Step。两者不冲突（都是适配器）。

---

## 六、要合伙人拍板的点

1. **走 A 还是 B（还是先 B 过渡、长期 A）？**
2. 若走 A：**用谁的机器？**——有没有本地 NVIDIA 显卡(≥6G)/Apple Silicon Mac？还是租国内云 GPU（按小时计费，谁来出）？
3. 民乐 LoRA 要不要排进计划？需要演奏者提供约 8+ 段干净的二胡/古筝录音素材。
4. 若走 B：能接受按次付费 + 数据出境第三方吗？预算大概多少/月？
