# 情绪音乐 · 小程序落地文档

> 把现有 HTML 原型（`emotion_music_prototype.html`）落地成微信小程序的完整指南。
> 环境：Windows + VS Code + Claude + 微信开发者工具。

---

## 0. 先认清一件事：是"重写"，不是"转换"

HTML 原型**不能**直接转成小程序。两者技术栈不同：

| | HTML 原型 | 微信小程序 |
|---|---|---|
| 结构 | `<div>` `<section>` | `<view>` `<text>` `<image>` |
| 样式 | CSS（`.html`/`.css`） | WXSS（`px` 改 `rpx`，部分选择器不支持） |
| 脚本 | 原生 JS（`fetch`、`getUserMedia`） | 小程序 JS（`wx.request`、`wx.getRecorderManager`） |
| 多页 | 一个文件里 `.screen` 切换 | 真·多页面（`pages/` 目录，`wx.navigateTo` 跳转） |

**但设计部分 100% 能搬：** 布局、配色、字号、动效逻辑、页面结构、交互流程、文案——这些都是已经定好的决策，重写时照抄即可。真正要重写的只是"语法外壳"。

**所以这份文档的用法：** 不是让 Claude "转换文件"，而是让 Claude 照着原型，**一个页面一个页面地用小程序语法重写**。原型是设计稿和逻辑参考，文档是重写的规则手册。

## 1. 一次性准备

1. **注册小程序账号**：到 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册，拿到 **AppID**。
   - 个人主体限制多（不能用微信支付、部分类目做不了）；如果以后要收费/正式运营，建议企业主体。
   - 注册很快，不要和"备案"混淆——备案是后面后端上线才需要的。
2. **下载微信开发者工具**（Windows 版）：搜索"微信开发者工具"官网下载安装。
3. **VS Code 准备好 Claude**（你已有）。

---

## 2. 工具分工（重要，别搞混）

- **VS Code + Claude** = 写代码的主力。让 Claude 生成/修改 WXML、WXSS、JS。
- **微信开发者工具** = 预览、调试、上传。它的模拟器实时显示效果；它的"调试器"看报错；它负责上传到微信后台。

**两个工具打开同一个项目文件夹**：VS Code 改文件存盘 → 开发者工具模拟器自动刷新。日常 99% 时间在 VS Code 写、瞄一眼开发者工具看效果。

**关键认知：Claude 看不到模拟器里的运行结果。** 报错了，要你从开发者工具的 console 复制错误信息贴给 Claude，它才能修。这是一个反复循环：开发者工具报错 → 贴给 Claude → Claude 改 → 再看。

## 5. 最大的坑：双层 TabBar（必须用自定义 tabBar）

这是整个落地里**最需要提前想清楚**的一点。

原型里有两套底部导航：
- **品牌层**：实验室 / 我的
- **活动层**（进活动后切换成）：活动主页 / 广场 / 我的活动

**微信原生 tabBar 是全局唯一的，无法在进入活动后自动换成另一套。** 所以必须用 **自定义 tabBar（custom-tab-bar）**：

1. `app.json` 里配 `"tabBar": { "custom": true, ... }`，把全部可能的 tab 页都列进 `list`。
2. 在项目根建 `custom-tab-bar/` 目录（`index.wxml`/`.wxss`/`.js`）。
3. 自定义 tab-bar 组件里维护一个状态：当前是"品牌层"还是"活动层"，据此渲染不同的两/三个 tab 项。
4. 进入活动（`enterAct`）时切到活动层那套；退出活动（`exitAct`）切回品牌层那套。

> 给 Claude 的提示词示例：
> "用微信小程序的自定义 tabBar（custom-tab-bar）实现双层导航：品牌层显示'实验室/我的'两个 tab，进入活动后切换成'活动主页/广场/我的活动'三个 tab。给我 app.json 配置 + custom-tab-bar 组件代码。"

## 6. 重写规则手册（让 Claude 遵守）

每次让 Claude 写小程序代码，**务必在提示词里强调这些**，否则它容易按网页习惯写错：

1. **标签**：`<div>`→`<view>`，纯文字用 `<text>`，图片用 `<image>`。
2. **样式单位**：`px` 一律改 `rpx`（750rpx = 屏幕宽）。原型里的 px 数值大致 ×2 转成 rpx 作起点，再微调。
3. **不支持的 CSS**：小程序 WXSS 不支持部分选择器和属性。尤其注意：
   - `backdrop-filter`（毛玻璃）—— 不支持/不稳定，避免。
   - 复杂 `filter: blur()` —— 性能差，能不用就不用。
   - 我们这版广场已经去掉了 blur 和毛玻璃，主要是实色 + SVG，相对安全。
4. **事件**：`onclick` → `bindtap`；`onchange` → `bindinput`/`bindchange`。
5. **数据驱动**：不能直接 `document.getElementById().innerHTML`。小程序是 `data` + `setData()` 驱动视图，列表用 `wx:for`，条件用 `wx:if`。原型里那些 `renderPlaza`/`renderQ` 的 DOM 拼接，要改成"改 data → 视图自动更新"。
6. **页面跳转**：`wx.navigateTo`（流程页）、`wx.switchTab`（tab 页）、`wx.navigateBack`（返回）。
7. **SVG**：小程序 `<image>` 可以显示 SVG（base64 或静态资源），但**不能像网页那样直接内联 `<svg>` 标签并用 CSS 动画**。广场的海滩场景要么：(a) 导出成图片用 `<image>`；(b) 用小程序的 `<cover-view>`/绝对定位 + 简单动画重做；(c) 用 canvas 画。最省事是 (a) 静态图 + 少量 CSS 动画做光球浮动。

## 7. 原型里的交互逻辑 → 小程序映射

原型的 JS 函数名我刻意贴着小程序习惯起的，对应关系：

| 原型函数 | 小程序做法 |
|---|---|
| `switchTab(id)` | `wx.switchTab` + 自定义 tabBar 切品牌层 |
| `enterAct/switchAct` | `wx.switchTab`/`navigateTo` + 自定义 tabBar 切活动层 |
| `openFlow(id)` | `wx.navigateTo`（流程页，无 tabBar） |
| `closeFlow/exitAct` | `wx.navigateBack` 或 `switchTab` |
| `renderQ/renderPlaza` | 改 `data` + `setData`，视图用 `wx:for`/`wx:if` |
| `toggleRec`（录音） | `wx.getRecorderManager()`，见第 8 节 |
| `runGen`（生成等待） | 调后端接口 + loading 态，见第 8 节 |
| `liked`/收藏 | 存后端或 `wx.setStorageSync` |

## 8. 后端：录音 → 分析 → 生成（核心，且只能在后端做）

小程序**不能直接调大模型**。必须：

```
小程序  →  你自己的后端（备案 https 域名）  →  多模态大模型 + Suno
```

- **录音**：小程序用 `wx.getRecorderManager()` 录音（要麦克风授权），得到音频文件 → `wx.uploadFile` 传到你的后端。
- **分析**：后端把音频转给**多模态大模型**（能"听"音频的，如 Gemini / GPT-4o-audio / 豆包等），拿到情绪、人格标签、关键词。
- **生成**：后端把分析结果组成 prompt 喂 **Suno**（注意 Suno 无官方公开 API，渠道要先确认），生成曲子。
- **返回**：后端把人格 + 曲线 + 音乐 URL 返回给小程序。
- **降级**：Suno 超时/失败时，后端返回预置兜底曲目，别让用户卡在生成页。

**分工铁律**：分析归多模态大模型，生成归 Suno。别让 Suno 去"分析"语音——方向反了。

**密钥永远在后端**，小程序前端碰不到任何 key。

## 9. 备案与域名白名单

- 小程序请求的域名必须是 **https + 已备案**，并在小程序后台"开发设置 → 服务器域名"里配成合法域名。
- **只需要备案"你自己后端的那一个域名"**，备案一次。大模型/Suno 的域名不用你备案（后端服务器对服务器调用，不受小程序白名单限制）。
- 备案最慢（工信部 ICP，可能数周），**趁早办**。后端建议放国内云（腾讯云/阿里云），访问快、备案顺。
- **开发期可绕过**：微信开发者工具 → 详情 → 本地设置 → 勾"不校验合法域名…"，模拟器即可连本地后端。**但真机预览和发布时此开关无效**，必须用备案域名。

## 10. 推荐的推进节奏（两条腿走，都不卡审核）

**第一阶段（现在就能做，不等任何审核）：**
1. 注册 AppID、装开发者工具、建项目。
2. 用 VS Code + Claude 把**纯前端 UI** 一页页重写：先 home/me 两个 tabBar 页 + 自定义 tabBar 跑通双层导航，再活动三页，再流程页。
3. 用假数据（照原型里的 `PLAZA`、`QUESTIONS`）让界面和交互在模拟器、真机预览里跑通。
4. 这阶段**不碰后端、不碰备案**，纯看界面和流程。

**第二阶段（并行）：**
1. 用 VS Code + Claude 在本地搭后端（Node/Python 都行），跑通"录音 → 分析 → (Suno 或占位) 生成"。开发期开发者工具勾"不校验域名"连本地后端。
2. 同时去办后端域名的 ICP 备案（最慢，早办）。

**第三阶段（上线/给人测）：**
1. 后端部署到备案好的公网服务器，域名填进小程序白名单。
2. 开发者工具"上传" → 设为**体验版**，加体验成员（黑客松评委/测试者扫码即用，不用正式发布审核）。
3. 要对所有人开放时，再"提交审核 → 发布"。

## 附：原型里已定好、可直接复用的设计资产

- **配色**：燕麦白底 `#ffffff`/`#f0eeea`，文字 `#1c1b1a`/`#6b6864`，描边 `#dcdad5`，赤陶点缀。广场海滩场景是低饱和雾青 + 燕麦沙 + 随时间变色（晨/昼/昏/夜四套）。
- **字体**：标题衬线（Songti SC），正文无衬线（PingFang SC）。
- **导航结构**：品牌层（实验室/我的）↔ 活动层（活动主页/广场/我的活动），流程页全屏无底栏。
- **核心流程**：活动主页 → 答题(语音优先/打字兜底) → 生成 → 结果(自动存档) → 分享/相似度。
- **隐私承诺**：答题前明示"你的回答只用于生成你的音乐，不会公开给任何人"；广场只展示结果不展示回答。
